# Публичный сайт и будущий кабинет Wedding4You

`wedding4you-site` (`52b2abe`) — статический сайт GitHub Pages на `wedding4u.co.il`. В этом PR ссылки «Войти» / «כניסה» ведут на статические страницы `/ru/app/` и `/app/`. Это предварительное описание пути: здесь нет регистрации, платежа, личных данных, загрузки документов или действующей сессии. Страницы закрыты от индексации и не публикуются этим PR.

`wedding4you` (`1f07da1`, draft PR #14) — отдельное локальное приложение NestJS: `/pilot` защищён паролем владельца и AES-GCM сейфом; `src/applicant-access.ts` выдаёт короткие коды для проверки отдельных черновиков. Это **не** готовая многопользовательская служба. `client-vault/` — отдельный синтетический прототип шифрования документов в браузере, который не принимает реальные документы и не подключён к `/pilot`.

Для открытого клиентского кабинета потребуется отдельный серверный контур. Планируемая цена доступа — разовый платёж ₪1 000 за пару и одно дело, без подписки; официальные сборы отдельно. Проверенный PayPal capture и подписанный webhook должны сверять конкретный order ID, merchant, сумму, валюту и состояние платежа до выдачи доступа. Неподтверждённый redirect клиента не является доказательством оплаты; неизвестный результат блокирует повторное списание до сверки. После подтверждения сервер выдаёт одноразовое приглашение, привязанное к конкретной покупке, с ограниченным сроком. Регистрация превращает его в клиентский аккаунт с защищённой сессией; каждый кейс и право второго заявителя привязываются к авторизованным пользователям. Записи процесса хранятся в частном серверном хранилище, изолированном по клиентам.

Документы остаются на устройстве: браузер шифрует их локально и не отправляет на статический сайт или сервер Wedding4You. Будущий интерфейс обязан объяснять резервную копию, потерю фразы и границы безопасности до выбора реального файла. Передача на официальный сайт, если потребуется, остаётся отдельным личным действием. Юридические согласия, подписи, проверка личности, государственные платежи и бронирование церемонии не выполняются статическим сайтом.

GitHub Pages не исполняет backend и не может защищать оплаченный доступ. Перед запуском `/app/` потребуется выбранный хостинг/API, приватная база, доменная маршрутизация, модель customer auth, выпуск приглашений и миграция с этой статической страницы. До этого ссылка в шапке остаётся информационной. Публичный деплой этим изменением не выполняется.
